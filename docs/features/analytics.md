# Аналитика GA4

Опциональная интеграция **Google Analytics 4** собирает воронку онбординга: шаги в браузере и
подтверждённые серверные события. По умолчанию она выключена. Пока интеграция выключена или
настроена не полностью, Minishop не отдаёт дескриптор, не загружает `gtag`, не добавляет
сторонние origins в CSP, не отправляет запросы в Google и не сохраняет события воронки.

## Настройка

Откройте **Система → Настройки → Аналитика** или задайте переменные окружения:

| Настройка | Переменная | Назначение |
| --- | --- | --- |
| Включение | `GA4_ENABLED` | Главный выключатель интеграции. |
| Measurement ID | `GA4_MEASUREMENT_ID` | ID веб-потока в формате `G-XXXXXXXXXX`. |
| API secret | `GA4_API_SECRET` | Секрет Measurement Protocol. Только сервер. |
| Debug mode | `GA4_DEBUG_MODE` | Передаёт `debug_mode` в браузерный тег и DebugView. |

Интеграция активна только при включённом флаге, корректном Measurement ID и непустом API secret.
Пустое значение любого из обязательных полей полностью выключает сбор и отправку. Изменения
настроек в админке применяются без перезапуска: браузерный конфиг читается при загрузке страницы,
а worker обновляет `GA4_*` перед каждой пачкой доставки.

API secret никогда не попадает в публичный bootstrap, ответы `/api/plugins/ga4funnel/config`,
браузерный адаптер, логи или тексты ошибок. В браузер передаются только Measurement ID и флаг
отладки.

## Согласие и ответственность

Отдельного баннера согласия нет: сбор начинается сразу после включения администратором. Включая
интеграцию, администратор сам отвечает за правовые основания, уведомление посетителей и
соответствие применимым правилам (включая GDPR и требования к cookies/аналитике). Если такие
согласия нужны, оставьте интеграцию выключенной или используйте собственный механизм согласия до
её включения.

## Что собирается в браузере

Публичный адаптер `/api/plugins/ga4funnel/signals.mjs` подключается Core после того, как
завершится существующий сбор рекламной атрибуции. Сам Google Tag не загружается на страницу
приложения: тег работает в скрытом same-origin iframe `/api/plugins/ga4funnel/frame` с
собственным строгим CSP. Автоматический сбор, привязанный к документу, видит только документ
frame; приложение пересылает в frame лишь разрешённые сигналы Core с синтетическими
`page_location`/`page_referrer` через проверенный `postMessage`. Адаптер не читает DOM и не
перехватывает `fetch` или `history`.

Важно: Google Tag — доверенный сторонний код. Same-origin iframe с `allow-scripts
allow-same-origin` не является границей безопасности против него: теоретически код тега может
прочитать `parent.location`, `parent.document.referrer` или другие данные родительской страницы.
CSP и валидация сообщений ограничивают автоматический сбор и явную передачу данных, но не
защищают от изменённого или вредоносного поведения самого Google-кода. Включайте интеграцию
только если доверяете этому коду и принимаете связанные риски. Отдельного баннера согласия нет:
сбор начинается сразу после включения администратором.

| Сигнал Core | Событие GA4 | Условие |
| --- | --- | --- |
| `screen_viewed` | `page_view` | Любой разрешённый экран; `page_location` синтетический: `<origin>/__/<screen>`, `page_title` = имя экрана. |
| `external_opened` | `app_download_click` | Только экраны `install` и `public_install`. |
| `app_opened` | `subscription_import_click` | Только экраны `install` и `public_install`. |
| `text_copied` | `subscription_link_copy` | Только экраны `install` и `public_install`. |
| `share_opened` | `install_guide_share` | Только экраны `install` и `public_install`. |
| `connect_opened` | `connect_instructions_opened` | Любой экран. |
| `auth_completed` | `login` | Диагностика перехода гость → аккаунт, не конверсия. |
| `trial_activated` | — | Игнорируется: серверное событие авторитетно. |

К каждому событию явно добавляются синтетические `page_location` (`<origin>/__/<screen>`) и
пустой `page_referrer`, а к просмотру экрана — безопасные поля `surface`, `screen`, `ad_code` и
очищенные `utm_*`. Автоматический `page_view` отключён, поэтому события enhanced measurement не
могут подставить текущий адрес документа или referrer. Сырые URL, токены подписки и share-ссылки,
email, Telegram ID, внутренние ID пользователя и произвольные payload'ы не передаются.

После авторизации адаптер читает GA client ID из cookie `_ga` (`GA1.1.<a>.<b>` → `<a>.<b>`) и
один раз за переход отправляет его на `POST /api/plugins/ga4funnel/bind`. Если cookie ещё нет,
делается несколько попыток с backoff; бесконечного опроса нет. Client ID не синтезируется из
идентификаторов пользователя. Привязка нужна, чтобы серверные события попали в ту же сессию GA4.

## Что отправляет сервер

Серверная часть использует GA4 Measurement Protocol и фиксированные endpoints Google. События
создаются только по подтверждённым доменным событиям Core:

| Событие GA4 | Источник | Дедупликация |
| --- | --- | --- |
| `sign_up` | `user.registered` (кроме технических `panel_sync`) | `sign_up:user:<id>` |
| `trial_started` | `trial.activated`, параметры `days`, `traffic_gb` | `trial_started:user:<id>` |
| `purchase` | `payment.succeeded` через durable outbox, параметры `transaction_id`, `value`, `currency`, `sale_mode`, `months` | `purchase:payment:<id>` |
| `vpn_first_connected` | `panel.webhook_received` с `user.first_connected` или подтверждение панели | `first_connected:user:<id>` |

Открытие checkout, применение промокода или нажатие кнопки оплаты не считаются покупкой. Первое
подключение засчитывается только по данным панели Remnawave (`firstConnectedAt`) или webhook;
ложные подключения не создаются. Если webhook пришёл раньше локальной привязки пользователя,
событие остаётся в очереди, а периодическая сверка (каждые 15 минут) находит пользователя по
panel UUID или Telegram ID и подтверждает результат.

Серверные параметры проходят allowlist. URL, токены, email, Telegram ID, user ID и данные
подписки не отправляются. Для событий не старше 72 часов добавляется `timestamp_micros`; более
старые доставляются без него. В каждом событии есть `engagement_time_msec`.

## Доставка, повторы и отключение

Worker забирает небольшие пачки событий с lease, отправляет их с таймаутом 5 секунд, без
redirects и с ограничением тела ответа. Успешный ответ (2xx) помечает событие отправленным. Ответ
4xx (кроме 429) окончательно отклоняет событие, а 429, 5xx и сетевые ошибки повторяются с
экспоненциальной задержкой до исчерпания попыток. Ошибки сохраняются только стабильным кодом;
API secret и полный URL с секретом не логируются.

Если у события ещё нет client ID, оно остаётся в очереди и повторяется позже. Через 24 часа без
привязки событие помечается `skipped` с кодом `binding_missing`. При выключении GA4 новые события
не отправляются; уже сохранённые строки остаются в БД и не уходят, пока интеграция снова не будет
включена.

## Ограничения

- DebugView и отчёты GA4 могут обновляться с задержкой; успешная отправка Measurement Protocol
  не гарантирует немедленное появление события в отчёте.
- Сквозная проверка воронки требует отдельной настройки GA4 (DebugView, отчёты, аудитории). Эта
  документация не заменяет проверку в интерфейсе Google Analytics.
- Один браузерный client ID привязывается к аккаунту; при смене аккаунта в том же браузере
  создаётся новая привязка после следующего перехода в авторизованное состояние.
- Интеграция не читает GA4 Data API и не показывает отчёты внутри Minishop.
