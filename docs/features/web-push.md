# Уведомления в браузере (Web Push)

Minishop умеет доставлять сервисные обновления, ответы поддержки и новости в браузер через
Web Push. Это встроенный плагин `web_push`; отдельный сервис, Telegram-бот или внешний
провайдер push не нужны. Пользователь включает уведомления в **Настройки -> Уведомления**,
и одна подписка покрывает обе категории: сервис/поддержку и новости/акции. Отдельного
маркетингового переключателя нет.

Канал не заменяет Telegram и email и не является обязательным для онбординга, установки
VPN-клиента или инструкций. Если Web Push выключен или браузер его не поддерживает,
остальные каналы и разделы Mini App работают как раньше.

## Настройка сервера

1. Сгенерируйте VAPID-пару:

   ```bash
   python -m bot.plugins.builtin.web_push.keygen
   ```

   Команда печатает `WEB_PUSH_VAPID_PUBLIC_KEY`, `WEB_PUSH_VAPID_PRIVATE_KEY` и пример
   `WEB_PUSH_VAPID_SUBJECT`. Приватный ключ — секрет: не коммитьте его, не вставляйте в
   тикеты, скриншоты и логи.

2. Задайте значения в `.env` или в **Админка -> Система -> Настройки -> Уведомления ->
   Web Push в браузере**:

   | Переменная | Назначение |
   | --- | --- |
   | `WEB_PUSH_ENABLED` | Включает плагин. По умолчанию `False`. |
   | `WEB_PUSH_VAPID_PUBLIC_KEY` | Base64url-несжатая публичная точка P-256, 65 байт. |
   | `WEB_PUSH_VAPID_PRIVATE_KEY` | Base64url-приватный скаляр P-256, 32 байта. Секрет. |
   | `WEB_PUSH_VAPID_SUBJECT` | Контакт `mailto:admin@example.com` или `https://...`. |
   | `WEB_PUSH_DELIVERY_TTL_SECONDS` | Срок хранения недоставленного сообщения push-сервисом, `0..86400`, по умолчанию `3600`. |

3. Перезапустите backend и worker после изменения ключей. Ключи должны быть парой: при
   несовпадении публичного и приватного ключа `web_push_configured` остаётся `False`,
   а статус в Mini App показывает «недоступно».

Публичный ключ отдаётся браузеру через `POST /api/plugins/web_push/status`. Приватный ключ
никогда не возвращается API и не попадает в OpenAPI/настройки в открытом виде.

## Поддерживаемые браузеры и ограничения

- Chrome, Edge, Firefox и Chromium-браузеры на Android — при HTTPS.
- Safari на macOS — при HTTPS и разрешении уведомлений для сайта.
- iPhone/iPad: **только** iOS/iPadOS 16.4+ и только для сайта, добавленного на экран
  «Домой». Установка приложения — обязательное условие iOS; сама установка не включает
  уведомления, пользователь должен отдельно нажать кнопку включения.
- Telegram Mini App и встроенные WebView не поддерживают Web Push. Экран предложит открыть
  Minishop в обычном браузере.
- Нужен HTTPS (secure context). Локальный `http://localhost` браузеры считают исключением,
  но для реального домена используйте TLS.

Подписка привязана к аккаунту и конкретному браузеру/устройству. Один аккаунт может иметь
несколько активных устройств. В карточке уведомлений виден список устройств, текущее
устройство помечено, а каждое устройство можно отключить отдельно. Отключение одного
устройства не меняет глобальную настройку и не затрагивает Telegram/email.

## Один opt-in и отключение

Пользователь нажимает «Включить уведомления в браузере» — только по этому явному действию:

1. браузер запрашивает разрешение;
2. используется существующий service worker `/sw.js`;
3. создаётся push-подписка;
4. подписка сохраняется на сервере и привязывается к текущему аккаунту;
5. включается единая настройка `push_notifications_enabled`.

Глобальное отключение в карточке выключает `push_notifications_enabled` и останавливает
обе категории на всех устройствах, сохраняя настройки Telegram и email. Чтобы убрать
только текущее устройство, используйте кнопку рядом с ним. При повторном входе браузер
синхронизирует активную подписку и перепривязывает её к текущему аккаунту.
Пассивная синхронизация (`POST /api/plugins/web_push/subscription/sync`) не создаёт
подписку и не снимает отзыв: отключённое устройство включается только явной кнопкой
(`POST /api/plugins/web_push/subscription`). Статус «Активно» требует серверного
подтверждения текущего устройства и включённого предпочтения. При ошибке включения
отзывается только текущий endpoint и восстанавливается прежнее предпочтение.

Безопасность: при выходе из аккаунта Mini App пытается отозвать текущую подписку до
очистки сессии, с коротким таймаутом; сбой сети не блокирует выход. Сервер независимо
перепроверяет владельца подписки и аккаунт получателя перед каждой доставкой, поэтому
смена аккаунта без выхода не отправит уведомления прежнего аккаунта. Проверка delivery,
lease, владельца, отзыва, срока действия, бана и предпочтения выполняется под блокировкой
конкретной подписки, которая удерживается до завершения HTTP-отправки. Перепривязка
и отзыв берут ту же блокировку. Enrollment всегда берёт сначала блокировку endpoint-hash,
затем (если строка уже существует) блокировку subscription id; worker, reassign и revoke
берут только subscription id и никогда не ждут endpoint-блокировку, поэтому порядок
блокировок не образует цикл. В PostgreSQL это transaction advisory lock, общий
для backend и worker; SQLite использует asyncio lock только внутри одного процесса
и не поддерживает раздельные backend/worker процессы.

## Доставка, повторы и хранение

- Уведомление сначала записывается в durable-очередь `ext_web_push_deliveries`; ответ
  `SENT` в core-контракте означает «принято в очередь», а не «показано на экране».
- Worker забирает очередь пачками с короткой lease-блокировкой, отправляет запрос без
  редиректов и с таймаутом 10 секунд.
- Ответы `201/2xx` — успех; `404/410` — подписка отозвана; `400/401/403/413` — постоянная
  ошибка; `429/5xx/сеть` — повтор с экспоненциальной задержкой до 6 попыток.
- При повторном запуске worker lease истекает, поэтому доставка продолжится. Гарантия —
  at-least-once: в редком окне между отправкой и записью результата браузер может получить
  дубль. Это не ошибка конфигурации и не повод отключать повторы.
- Для рассылок результат push-доставки сначала фиксируется в очереди плагина, а затем
  отдельная outbox-очередь обновляет статус в Core. Сбой этого обновления повторяется
  без повторной отправки push; отметка об успешном отчёте ставится только после ответа Core.
- Перед каждой попыткой перепроверяются существование и владелец подписки, бан пользователя,
  `push_notifications_enabled`, глобальный `USER_NOTIFICATION_PUSH_ENABLED` и готовность
  плагина.
- События с секретами авторизации, коды, пароли и служебные admin-only уведомления в push
  не попадают. Текст ограничен, URL нормализуется до безопасного same-origin пути; ссылки
  на `/s/<token>`, внешние домены и query-параметры с `token`, `secret`, `code`, `session`
  отбрасываются.

## Приватность и хранение данных

Таблицы плагина: `ext_web_push_subscriptions` и `ext_web_push_deliveries`. Endpoint и ключи
браузера (`p256dh`, `auth`) хранятся только как AES-GCM ciphertext; ключ шифрования
выводится через HKDF-SHA256 из текущего VAPID private key. В открытом виде хранится только
SHA-256 hash endpoint для идентификации устройства. После смены VAPID private key старые
записи расшифровать нельзя: worker отзывает их и помечает очередь как пропущенную, поэтому
после ротации ключей пользователям нужно включить уведомления заново.

Сервер не пишет endpoint, ключи, JWT и содержимое push в логи. В интерфейс возвращаются
только id устройства, метка, время создания/последней активности и признак текущего
устройства. Токены доступа и share-ссылки в тексте уведомления не используются.

## Резервное копирование и удаление

- Обычный backup БД включает таблицы `ext_web_push_*`; после восстановления на сервер с
  тем же VAPID private key подписки продолжают работать.
- При восстановлении на другой сервер/ключи или после ротации ключей записи считаются
  недействительными и отзываются worker-ом при первой попытке.
- Пользователь может удалить отдельное устройство в карточке, глобально выключить push или
  очистить данные сайта в браузере. Очистка данных сайта удаляет браузерную подписку, но
  серверная запись будет отозвана при следующей попытке доставки (`404/410`).
- Записи не содержат открытых endpoint или ключей браузера. При удалении пользователя
  подписки больше не доставляются; для полного удаления связанных строк удалите их из
  `ext_web_push_subscriptions`/`ext_web_push_deliveries` вместе с аккаунтом.

## Ограничения

- Нет гарантии отображения на уровне ОС: браузер, настройки питания, режим «не беспокоить»
  и разрешения пользователя остаются вне контроля сервера.
- Административная рассылка через push будет подключаться отдельной задачей; этот плагин
  предоставляет только helper постановки в очередь и worker доставки.
- Для iOS требуется установленное приложение; в Telegram WebView push недоступен.
- Ключи и endpoint нельзя восстановить из интерфейса: при потере VAPID private key
  выпустите новую пару и попросите пользователей включить уведомления заново.
